## 작업 내용
- 발표 전 최종 정리 방향을 점검했다.
  - 내가 구현한 기능을 단순 기능 나열이 아니라 `구독 기반 가족 공유`, `냉장고 사진 등록`, `위치 기반 재료 나눔`의 서비스 가치 중심으로 설명하기로 정리했다.
  - 발표에서 기능별 핵심 소스는 전체 코드가 아니라 가장 중요한 코드 1부분만 보여주는 방향으로 잡았다.

- 발표 예상 질문 대응 내용을 복습했다.
  - OpenAI Vision을 사용한 이유
  - OCR과 Vision 분석의 차이
  - AI 결과를 바로 등록하지 않고 후보 검증 흐름으로 둔 이유
  - 예외 처리, 보안, 비용 관리, 사용량 로그 저장 방식
  - 위치 기반 나눔에서 Kakao Maps와 Geolocation을 사용한 방식

- 기능별 핵심 구현 포인트를 정리했다.
  - 구독 기반 가족 공유는 구독 여부에 따라 가족 관리 접근을 제어하고, 가족 초대와 공유 냉장고 전환을 제공한다.
  - 냉장고 사진 등록은 OpenAI Vision으로 식재료 후보를 분석하고, 백엔드에서 사전 재료와 매칭한 뒤 사용자가 확인 후 등록하는 구조이다.
  - 위치 기반 재료 나눔은 사용자의 현재 위치와 게시글 위치 사이의 거리를 계산해 반경 안의 나눔 글만 보여주는 구조이다.

- 발표 답변 방향을 정리했다.
  - AI 기능은 정확성을 완전히 보장한다고 말하지 않고, 오인식 가능성을 전제로 검증 가능한 후보 승인 구조를 두었다고 설명한다.
  - 보안 측면에서는 OpenAI API Key를 프론트에 노출하지 않고 Agent 서버 환경변수로 관리했다고 설명한다.
  - 비용 측면에서는 Vision API 호출 비용 때문에 구독 기능으로 분리했고, usage 정보를 백엔드에 저장해 관리자 페이지에서 확인할 수 있다고 설명한다.

## 문제 해결
- 발표에서 소스코드 질문이 나올 가능성에 대비했다.
  - 프론트는 사용자 진입, 화면 상태, API 호출을 담당한다.
  - 백엔드는 권한 검증, 데이터 저장, 사전 재료 매칭, 거리 계산을 담당한다.
  - Agent 서버는 OpenAI Vision 분석과 응답 파싱을 담당한다.

- 발표 문구가 너무 개발자 중심으로 보이지 않도록 조정했다.
  - 변수명이나 API명 위주 설명보다 사용자가 이해할 수 있는 기능 단위 표현을 우선하기로 했다.
  - 단, 트러블슈팅이나 핵심 구현 설명에서는 코드 1부분만 캡처해 기술적 근거를 보여주는 방식으로 정리했다.

## 배운 점
- 발표에서는 “무엇을 만들었는가”보다 “왜 그렇게 설계했는가”가 더 중요하다.
- AI 기능은 모델 호출 자체보다 오인식, 검증, 예외 처리, 보안, 비용 관리까지 함께 설명해야 설득력이 생긴다.
- 기능별 핵심 코드는 많이 보여주는 것보다, 발표 메시지를 뒷받침하는 대표 코드 1개를 고르는 것이 효과적이다.
