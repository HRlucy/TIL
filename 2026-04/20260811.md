### 1. 냉장고 사진 기반 재료 등록 기능 구현
- 냉장고 화면에 `냉장고 사진 등록` 버튼을 추가했다.
- 구독자만 냉장고 사진 등록 기능을 사용할 수 있도록 프론트/백엔드 양쪽에서 제한했다.
- 미구독자가 버튼을 누르면 구독 안내 화면으로 이동하도록 처리했다.
- 영수증 등록과 동일하게 `사진 찍기` / `갤러리에서 가져오기` 선택 UI를 적용했다.
- 사진 선택 후 바로 분석하지 않고, 사용자가 `냉장고 사진 분석` 버튼을 눌러야 분석되도록 플로우를 맞췄다.

### 2. OpenAI Vision 기반 Agent API 추가
- Agent-dev FastAPI 서버에 냉장고 사진 분석 API를 추가했다.
- 프론트에서 이미지를 base64로 변환해 Agent에 전달한다.
- Agent는 OpenAI Vision을 사용해 이미지 속 식재료 후보를 JSON으로 반환한다.
- 응답에는 재료 후보뿐 아니라 `usage` 정보도 포함하도록 확장했다.
- 영수증 OCR Agent 응답에도 동일하게 `usage` 정보를 포함하도록 맞췄다.

### 3. 백엔드 냉장고 사진 API 추가
- `/api/v1/fridge-photos` 하위 API를 추가했다.
- 주요 기능:
  - 냉장고 사진 업로드
  - Agent 분석 결과 저장
  - 사전 재료 자동 매칭
  - 후보 목록 조회
  - 후보 수정
  - 후보 제외
  - 후보 냉장고 등록
- MVP에서는 새 테이블을 만들지 않고 기존 `receipt_analysis`, `receipt_analysis_items` 구조를 재사용했다.
- 냉장고 사진으로 등록된 항목은 memo를 `냉장고 사진으로 등록`으로 구분했다.

### 4. AI 사용량 로그 연동
- 냉장고 사진 분석과 영수증 OCR도 관리자 AI 사용량에 남도록 연결했다.
- `LlmFeatureType`에 다음 타입을 추가했다.
  - `RECEIPT_OCR`
  - `FRIDGE_PHOTO_ANALYSIS`
- Agent가 반환한 token/cost 정보를 백엔드에서 `llm_usage_logs`에 저장하도록 했다.
- 관리자 페이지 AI 사용량 탭에 `영수증 OCR`, `냉장고 사진` 필터와 라벨을 추가했다.
- DB check constraint 오류를 해결하기 위해 Flyway migration을 추가했다.
  - `V22__allow_ocr_llm_usage_feature_types.sql`

### 5. 이미지 업로드 안정화
- 휴대폰 사진 업로드 시 `413 Payload Too Large`가 발생했다.
- 백엔드 multipart 제한을 10MB로 명시했다.
- 프론트에서 업로드 전 이미지를 최대 1600px, JPEG 품질 0.82로 압축하도록 했다.
- 휴대폰에서 Agent 직접 호출 시 `failed to fetch`가 발생해 Next 프록시 라우트를 추가했다.
- 브라우저는 `/agent/...` 상대 경로로 호출하고, Next 서버가 `127.0.0.1:8000` Agent로 프록시한다.

### 6. 공산품 별칭 매칭 보강
- 짜파게티가 `파`로 인식되는 문제를 확인했다.
- Agent 프롬프트만으로는 불안정하므로 백엔드 별칭 매핑을 추가했다.
- 예시:
  - 짜파게티, 신라면, 진라면, 너구리, 불닭볶음면 → 라면
  - 햇반, 오뚜기밥 → 즉석밥
  - 스팸, 리챔 → 햄
  - 참치캔 → 참치
  - 비비고만두, 고향만두 → 만두
  - 서울우유, 매일우유 → 우유
- 이후 라면류, 즉석밥, 통조림, 냉동식품, 유제품, 소스류, 음료류까지 별칭 범위를 확장했다.
- 같은 내용을 냉장고 사진 Agent 프롬프트와 영수증 OCR 프롬프트에도 반영했다.

### 7. 프론트 UI/UX 수정
- 홈 화면 모바일에서 상단 프로필/인사/점수 버튼 배치가 깨지는 문제를 수정했다.
- 모바일에서는 버튼 묶음이 아래 줄로 내려가도록 반응형 CSS를 추가했다.
- 냉장고 탭에 진입하면 기본으로 `내 냉장고`가 선택되도록 수정했다.
- 영수증 등록도 냉장고 사진 등록처럼 미구독자는 구독 안내로 이동하도록 변경했다.
- 영수증 등록 명칭을 `영수증으로 재료 등록`에서 `영수증 등록`으로 정리했다.
- React style warning을 해결했다.
  - `border` / `borderTop`
  - `borderColor` / `borderTopColor`
  - shorthand와 longhand를 섞지 않도록 방향별 border 속성으로 분리했다.

## 배운 점

### 1. AI 인식 결과는 백엔드 보정이 필요하다
OpenAI Vision은 사진을 보고 후보를 잘 추출하지만, 서비스 DB에 바로 넣을 수 있는 형태로 항상 반환하지는 않는다. 특히 짜파게티처럼 포장된 공산품은 이미지 일부를 보고 엉뚱한 재료로 해석할 수 있다. 따라서 AI 결과를 그대로 믿기보다 백엔드에서 별칭 매핑과 product 사전 매칭을 반드시 거쳐야 한다.

### 2. 모바일 이미지 업로드는 원본 크기를 고려해야 한다
휴대폰 카메라 사진은 용량이 크고, base64로 변환하면 크기가 더 커진다. 이미지 업로드 기능은 서버 제한만 늘리는 것보다 프론트에서 먼저 리사이즈/압축하는 방식이 안정적이다.

### 3. 휴대폰 브라우저의 localhost는 맥북이 아니다
맥북에서 실행 중인 Agent가 `localhost:8000`이어도 휴대폰 브라우저에서 `localhost`는 휴대폰 자신을 의미한다. 모바일 테스트에서는 Next 프록시나 맥북 IP 기반 접근이 필요하다.

### 4. DB enum/check constraint도 기능 확장 시 같이 봐야 한다
Java enum에 새 feature type을 추가해도 DB check constraint가 예전 값만 허용하면 insert가 실패한다. enum성 컬럼을 확장할 때는 Flyway migration으로 DB 제약조건도 함께 변경해야 한다.

### 5. React inline style은 shorthand와 longhand를 섞으면 경고가 난다
`border`와 `borderTop`, `borderColor`와 `borderTopColor`를 같은 요소에서 섞으면 React가 rerender 중 스타일 충돌 경고를 낸다. 방향별 속성으로 명확히 분리하는 게 안전하다.
