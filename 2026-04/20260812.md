## 작업 내용

### 주변 재료 나눔 기능 구현
- 수박, 양배추처럼 혼자 다 먹기 어려운 재료를 주변 사용자와 나눌 수 있는 기능을 구현했다.
- 기능명은 최종적으로 `재료 함께 나눔`으로 정리했다.
- 일반 기능으로 제공하는 방향으로 잡았고, 구독 기능과는 분리했다.

### 백엔드
- 위치 기반 재료 나눔 API를 추가했다.
- 나눔 글 등록, 주변 나눔 조회, 내 나눔 조회, 선착순 참여, 참여 취소, 마감, 취소 기능을 구현했다.
- 나눔 글은 위도/경도 기반으로 저장하고, 조회 시 현재 위치 기준 반경 안의 글만 내려주도록 했다.
- 반경 기준은 `500m`, `1km`, `2km`로 조정했다.
- 나눔 재료는 직접 문자열 입력이 아니라 기존 사전 재료 `productId` 기준으로 저장하도록 수정했다.
- Flyway 마이그레이션을 추가했다.
  - `V23__create_community_share_tables.sql`
  - `V24__add_product_id_to_community_share_posts.sql`

### 프론트엔드
- 하단/사이드 메뉴에 `나눔` 탭을 추가했다.
- `재료 함께 나눔` 화면을 추가했다.
- 카카오맵 SDK를 연결해 주변 나눔 글이 지도에 표시되도록 했다.
- 나눔 글은 지도 위 말풍선으로 표시되고, 클릭 시 상세 카드가 강조되도록 구현했다.
- 위치 권한 동의 시 현재 위치 기준으로 지도와 목록을 조회하도록 했다.
- 카카오맵 SDK 설정 중 JavaScript 키 마지막에 잘못 붙은 특수문자 때문에 지도가 로드되지 않는 문제를 확인하고 수정했다.
- 나눔 등록 폼은 냉장고 관리의 재료 추가 방식과 동일하게 `재료 이름 검색 → 검색 결과 선택 → productId 저장` 방식으로 맞췄다.
- 화면 헤더 문구와 스타일을 기존 `냉장고 관리`, `문의하기` 화면 톤에 맞춰 정리했다.

### 환경 및 설정
- 카카오 Developers에서 JavaScript SDK 도메인 설정이 필요함을 확인했다.
- 실제 접속 주소가 `http://192.168.0.24:3000`이면 해당 주소도 JavaScript SDK 도메인에 등록해야 한다는 점을 확인했다.
- 프론트 `.env.local`에 `NEXT_PUBLIC_KAKAO_MAP_APP_KEY`를 추가했다.
- 카카오맵 키는 백엔드 `application-secret.env`가 아니라 프론트 `.env.local`에 들어가야 한다.

### 최신화
- Backend, Frontend, Agent-dev를 최신 원격 기준으로 업데이트했다.
- 원격 feature 브랜치들이 삭제되어 있어 추적 브랜치를 정리했다.
  - Backend: `origin/dev`
  - Frontend: `origin/main`
  - Agent: `origin/dev`
- 프론트 최신화 중 `Sidebar.js` 충돌이 발생했고, 구독 관리 메뉴와 나눔 메뉴가 모두 유지되도록 해결했다.
- `next.config.js`는 푸시 대상에서 제외했다.

## 트러블슈팅

### 지도 로드 실패
- 현상: `지도를 불러오지 못했습니다` 메시지가 표시됨.
- 원인:
  - 처음에는 JavaScript SDK 도메인 설정 위치를 혼동했다.
  - 이후 실제 원인은 `.env.local`의 카카오 JavaScript 키 끝에 잘못된 특수문자 `₩`가 붙어 있었던 것.
- 해결:
  - 키 값을 영문/숫자 32자리로 정리했다.
  - SDK GET 요청이 정상 JS 응답을 반환하는 것을 확인했다.

### 위치 기반 조회
- 현상: 현재 위치 대신 서울시청 기본 위치가 표시됨.
- 원인:
  - 위치 권한 실패/timeout 시 fallback 좌표를 사용하도록 되어 있었음.
  - 한때 `isSecureContext` 조건으로 사전 차단을 넣어 실제 동작을 막을 가능성이 있었다.
- 해결:
  - 사전 차단 제거
  - 브라우저의 `navigator.geolocation`을 직접 호출하도록 수정
  - 실패 시 안내 문구를 표시하도록 개선

### 예외 핸들러 충돌
- 현상: 백엔드 실행 시 `Ambiguous @ExceptionHandler` 오류 발생
- 원인:
  - 기존 `IllegalArgumentException` 핸들러가 있는데 새 핸들러가 같은 예외를 다시 잡고 있었음
- 해결:
  - 새 핸들러는 `IllegalStateException`만 처리하도록 수정

## 회고
- 위치 기반 기능은 지도 SDK 설정, 브라우저 위치 권한, 실제 접속 도메인까지 함께 맞아야 정상 동작한다.
- 외부 SDK 문제는 코드만 보기보다 실제 요청 URL의 HTTP 상태와 응답을 확인하는 것이 빠르다.
- 나눔 재료는 자유 입력보다 기존 사전 재료 `productId` 기준으로 관리하는 것이 DB 정합성과 검색/분류에 더 안전하다.
