# TIL - CI/CD와 AWS 배포

## 1. 학습 내용

애플리케이션 개발 이후 서버에 배포되는 과정과 이를 자동화하는 CI/CD 개념을 학습했다.

주요 학습 내용은 다음과 같다.

* CI/CD
* GitHub Actions와 Jenkins
* Argo CD와 Kubernetes
* AWS EC2와 Elastic Beanstalk
* VPC와 기본 네트워크 설정

---

## 2. CI/CD

CI/CD는 코드의 빌드, 테스트, 배포 과정을 자동화하는 방식이다.

```text
코드 작성
→ Git push
→ 빌드 및 테스트
→ 배포 파일 또는 Docker 이미지 생성
→ 서버 배포
```

| 구분 | 의미                               | 역할                             |
| -- | -------------------------------- | ------------------------------ |
| CI | Continuous Integration           | 변경된 코드를 자동으로 빌드하고 테스트          |
| CD | Continuous Delivery / Deployment | 검증된 결과물을 배포 가능한 상태로 만들거나 실제 배포 |

CI는 문제가 있는 코드가 주요 브랜치에 반영되는 것을 줄여준다.
CD는 서버 접속, 파일 업로드, 실행과 같은 반복적인 배포 작업을 자동화한다.

---

## 3. GitHub Actions와 Jenkins

### GitHub Actions

GitHub Actions는 GitHub 저장소의 이벤트를 기준으로 작업을 자동 실행하는 도구이다.

```text
GitHub에 push
→ 의존성 설치
→ 빌드 및 테스트
→ Docker 이미지 생성
→ 서버 배포
```

GitHub 저장소와 바로 연동할 수 있어 개인 및 팀 프로젝트에서 비교적 쉽게 사용할 수 있다.

### Jenkins

Jenkins는 별도의 서버에 설치하여 사용하는 CI/CD 자동화 도구이다.

플러그인이 많고 설정 자유도가 높아 기업 환경에서 널리 사용되지만, Jenkins 서버를 직접 관리해야 한다는 부담이 있다.

| 도구             | 특징                          |
| -------------- | --------------------------- |
| GitHub Actions | GitHub 연동이 쉽고 설정이 간단함       |
| Jenkins        | 확장성과 자유도가 높지만 별도 서버 관리가 필요함 |

---

## 4. Kubernetes와 Argo CD

### Kubernetes

Kubernetes는 여러 컨테이너를 안정적으로 실행하고 관리하는 플랫폼이다.

주요 기능은 다음과 같다.

* 컨테이너 실행 및 배치
* 장애 발생 시 자동 재시작
* 트래픽 분산
* 배포 버전 관리
* 자동 확장
* 환경 변수와 비밀값 관리

```text
Docker = 컨테이너 생성 및 실행
Kubernetes = 여러 컨테이너의 운영과 관리
```

### Argo CD

Argo CD는 Kubernetes 환경에서 사용하는 GitOps 기반 배포 도구이다.

Git 저장소에 작성된 배포 설정과 실제 Kubernetes 상태를 비교하고, 두 상태가 다르면 Git의 설정에 맞게 동기화한다.

```text
Git 배포 설정 변경
→ Argo CD가 변경 감지
→ Kubernetes 상태 비교
→ 변경 내용 반영
```

일반적으로 GitHub Actions가 애플리케이션을 빌드하고 Docker 이미지를 생성하면, Argo CD가 해당 이미지를 Kubernetes에 배포하는 구조로 사용할 수 있다.

## 5. AWS EC2 배포

EC2는 AWS에서 제공하는 가상 서버이다.

Ubuntu와 같은 운영체제를 선택한 뒤 Java, Docker, Nginx 등을 직접 설치하여 애플리케이션을 실행할 수 있다.

```text
EC2 생성
→ SSH 접속
→ 실행 환경 설치
→ 애플리케이션 배포
→ 서버 실행
→ 보안 그룹 설정
→ 외부 접속 확인
```

EC2는 설정 자유도가 높지만 다음 항목을 직접 관리해야 한다.

* 서버 환경
* 애플리케이션 실행
* 포트와 방화벽
* 로드 밸런싱
* 자동 확장
* 모니터링

---

## 6. Elastic Beanstalk

Elastic Beanstalk는 애플리케이션 배포에 필요한 AWS 인프라를 자동으로 구성해주는 서비스이다.

애플리케이션 파일이나 Docker 이미지를 배포하면 다음과 같은 기능을 구성하고 관리해준다.

* EC2 인스턴스 생성
* 로드 밸런싱
* 자동 확장
* 상태 모니터링
* 애플리케이션 버전 관리

여기서 프로비저닝은 애플리케이션 실행에 필요한 서버, 네트워크, 런타임 등의 환경을 준비하는 과정을 의미한다.

---

## 7. EC2와 Elastic Beanstalk 비교

| 구분     | EC2             | Elastic Beanstalk  |
| ------ | --------------- | ------------------ |
| 관리 대상  | 서버              | 애플리케이션 실행 환경       |
| 설정 자유도 | 높음              | 상대적으로 제한적          |
| 운영 방식  | 직접 설정 및 관리      | AWS가 주요 인프라를 자동 구성 |
| 적합한 경우 | 서버 환경을 직접 제어할 때 | 빠르게 배포 환경을 구성할 때   |

단순한 프로젝트 배포는 EC2만으로도 가능하다.
로드 밸런싱, 자동 확장, 모니터링까지 편리하게 구성하려면 Elastic Beanstalk를 사용할 수 있다.

---

## 8. VPC

VPC는 AWS 내부에 만드는 사용자 전용 가상 네트워크이다.

VPC 안에서 다음 항목을 설정할 수 있다.

* IP 주소 범위
* Subnet
* Routing Table
* Internet Gateway
* Security Group
* Network ACL

EC2 인스턴스도 특정 VPC와 Subnet 안에 생성된다.
외부에서 접속하려면 인터넷 연결 경로와 보안 그룹 설정이 올바르게 구성되어야 한다.

---

## 9. AWS 배포 시 확인 사항

로컬에서는 정상적으로 실행되더라도 AWS 환경에서는 네트워크 설정 때문에 접속되지 않을 수 있다.

배포 후에는 다음 항목을 확인해야 한다.

```text
애플리케이션 빌드
→ 서버 또는 배포 환경 준비
→ 환경 변수 설정
→ 애플리케이션 배포
→ 실행 상태 확인
→ 포트 확인
→ 보안 그룹 확인
→ 외부 접속 테스트
```

접속 문제가 발생하면 다음 내용을 점검한다.

* 애플리케이션 프로세스가 실행 중인지
* 애플리케이션이 올바른 포트에서 실행되는지
* 보안 그룹에서 해당 포트를 허용했는지
* 퍼블릭 IP 또는 도메인이 올바른지
* 방화벽과 라우팅 설정이 올바른지

---

## 10. 핵심 정리

1. CI/CD는 빌드, 테스트, 배포 과정을 자동화한다.
2. GitHub Actions와 Jenkins는 CI/CD 파이프라인을 구성하는 도구이다.
3. Kubernetes는 여러 컨테이너의 실행과 운영을 관리한다.
4. Argo CD는 Git의 배포 설정을 Kubernetes에 동기화한다.
5. EC2는 사용자가 직접 관리하는 AWS 가상 서버이다.
6. Elastic Beanstalk는 EC2, 로드 밸런싱, 자동 확장 등의 배포 환경을 자동으로 구성한다.
7. VPC는 AWS 리소스가 배치되는 가상 네트워크이다.
8. AWS 배포에서는 애플리케이션뿐 아니라 포트, 보안 그룹, 라우팅 설정도 함께 확인해야 한다.
