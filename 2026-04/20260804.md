# Docker와 Cloud 기초 정리

## 1. Dockerfile과 이미지 빌드

Dockerfile은 Docker 이미지를 만들기 위한 실행 환경과 작업 순서를 작성하는 파일이다.

현재 디렉터리의 Dockerfile을 기준으로 이미지를 만들려면 다음 명령어를 사용한다.

```bash
docker build -t 이미지명 .
```

- `docker build`: Docker 이미지를 빌드한다.
- `-t 이미지명`: 생성할 이미지의 이름이나 태그를 지정한다.
- `.`: 현재 디렉터리를 빌드 컨텍스트로 사용한다.

## 2. JRE와 JDK

- **JRE(Java Runtime Environment)**: Java 프로그램을 실행하기 위한 환경이다.
- **JDK(Java Development Kit)**: JRE에 컴파일러 등의 개발 도구가 추가된 개발 환경이다.

이미 빌드된 Spring Boot JAR 파일을 실행하기만 한다면 JRE 이미지로 충분하다.

## 3. 이미지와 컨테이너

- **이미지(Image)**: 애플리케이션 실행에 필요한 환경과 파일을 담은 실행 템플릿이다.
- **컨테이너(Container)**: 이미지를 기반으로 애플리케이션이 실제로 실행되고 있는 상태이다.

## 4. EC2 파일 전송과 외부 접속

### SCP로 파일 전송하기

`scp`를 사용하면 로컬 파일을 EC2 서버로 전송할 수 있다.

```bash
scp -i 키파일.pem 로컬파일 사용자명@EC2주소:원격경로
```

### EC2 보안 그룹

EC2에서 서버를 실행하더라도 보안 그룹의 인바운드 규칙에서 해당 포트를 허용해야 외부에서 접속할 수 있다.

예를 들어 애플리케이션이 `8080` 포트에서 실행된다면 보안 그룹에서도 `8080` 포트를 열어야 한다.

## 5. 포트 사용 프로세스 확인

다음 명령어로 `8080` 포트를 사용하는 프로세스를 확인할 수 있다.

```bash
lsof -i :8080
```

## 6. Docker Compose

Docker Compose는 여러 컨테이너의 설정을 하나의 파일에 정의하고 한 번에 실행하는 도구이다.

Compose 환경에서는 같은 네트워크에 연결된 컨테이너끼리 서비스 이름을 호스트 이름처럼 사용하여 통신할 수 있다.

예를 들어 데이터베이스 서비스 이름이 `db`라면 다른 서비스에서 `db:3306`과 같은 주소로 접근할 수 있다.

## 7. Docker Network와 Volume

### Docker Network

Docker Network는 컨테이너 간 통신을 지원하는 가상 네트워크이다.

### Docker Volume

Docker Volume은 다음과 같은 목적으로 사용한다.

- 컨테이너가 삭제되어도 데이터를 유지한다.
- 여러 컨테이너가 데이터를 공유한다.
- 데이터를 컨테이너의 생명 주기와 분리하여 관리한다.

## 8. Cloud와 서비스 유형

Cloud는 서버와 인프라 자원을 직접 소유하지 않고 필요한 만큼 빌려 사용하는 방식이다.

| 유형 | 의미 | 제공 범위 |
| --- | --- | --- |
| IaaS | Infrastructure as a Service | 서버, 스토리지, 네트워크 등의 인프라 |
| PaaS | Platform as a Service | 애플리케이션 실행 및 개발 플랫폼 |
| SaaS | Software as a Service | 사용자가 바로 이용할 수 있는 완성된 소프트웨어 |

## 9. 주요 AWS 서비스

| 서비스 | 역할 |
| — | — |
| EC2 | 가상 서버를 제공한다. |
| S3 | 파일 등의 데이터를 객체 형태로 저장한다. |
| IAM | 사용자, 역할 및 AWS 자원의 접근 권한을 관리한다. |
