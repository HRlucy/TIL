## 작업 내용
- 발표 자료 구성을 정리했다.
  - Canva PDF `냉파마스터_2차.pdf`를 확인해 김혜령 발표 파트가 8~9페이지임을 파악했다.
  - 발표 주제를 `구독 기반 가족 공유`, `냉장고 사진 등록`, `위치 기반 재료 나눔` 중심으로 재정리했다.
  - 기능 설명은 화면 캡처 중심, 트러블슈팅은 핵심 코드 일부를 함께 보여주는 방향으로 잡았다.

- 구독 기반 가족 공유 발표 내용을 정리했다.
  - 가족 냉장고 공유
  - 가족 구성원 초대
  - 재료 나눔·요청
  - 장보기 목록 공유
  - 발표용 핵심 코드는 구독 상태에 따라 가족 관리 접근을 제어하는 `handleOpenFamilyManagement`로 선정했다.

- 냉장고 사진 등록 발표 내용을 정리했다.
  - 냉장고 사진 등록은 OCR이 아니라 OpenAI Vision 기반 이미지 분석 기능으로 설명하기로 했다.
  - 영수증 등록은 텍스트를 읽는 OCR 성격이 강하고, 냉장고 사진 등록은 사진 속 식재료 후보를 인식하는 Vision 분석이라고 구분했다.
  - 발표용 핵심 코드는 Agent 서버의 `client.responses.create(...)` OpenAI Vision 호출 부분으로 선정했다.

- 위치 기반 재료 나눔 발표 내용을 정리했다.
  - 위치 기반 지도는 Kakao Maps JavaScript API를 사용했다고 설명하기로 했다.
  - 사용자의 현재 위치는 브라우저 Geolocation API로 가져오고, 백엔드에서는 위도·경도·반경 기준으로 주변 나눔 게시글을 필터링하는 구조로 정리했다.
  - 발표용 핵심 코드는 거리 계산 후 반경 안의 게시글만 필터링하는 `CommunityShareService` 로직으로 선정했다.

- 발표 슬라이드에 넣을 문구를 작성했다.
  - `구독 혜택 강화 → 지역 기반 서비스 확장`
  - `구독 기반 가족 공유`
  - `냉장고 사진 재료 인식`
  - `위치 기반 재료 나눔`
  - 기능 흐름보다는 사용자가 이해하기 쉬운 기능 이름 중심으로 문구를 다듬었다.

- 서버 기동 오류를 해결했다.
  - Spring Boot 실행 중 Flyway가 `V1__baseline.sql`과 `V1__baseline 2.sql`을 동시에 발견해 서버가 기동되지 않았다.
  - 소스에는 중복 migration이 없었고, `build/resources/main/db/migration` 산출물에만 복제 파일이 남아 있었다.
  - `./gradlew clean compileJava`, `./gradlew processResources`로 build 산출물을 정리했다.
  - 정리 후 `build/resources/main/db/migration/V1__baseline.sql`만 남은 것을 확인했다.

- 프론트 운영 반영 상태를 확인했다.
  - 가족 냉장고 관련 수정이 운영에 반영되지 않은 이유를 확인했다.
  - 로컬 커밋과 원격 main 반영 여부를 분리해서 확인했고, PR merge와 운영 배포는 별도 단계임을 정리했다.
  - `origin/main`에 수정 커밋이 merge된 것은 확인했지만, 운영 사이트 반영은 프론트 재배포와 CDN/브라우저 캐시 영향을 받을 수 있음을 정리했다.

- 프론트 가족 냉장고 UI를 수정했다.
  - 공유 가족 냉장고에서도 `냉장고 사진 등록` 버튼이 보이도록 조건을 수정했다.
  - `영수증 등록`과 `냉장고 사진 등록` 버튼을 2열 그리드로 정리했다.
  - 재료 카드의 `사용`, `수정`, `나눔`, `요청`, `삭제` 버튼이 모바일에서 세로로 떨어지지 않도록 가로 스크롤 형태로 변경했다.

- 프론트 PR을 생성했다.
  - 브랜치: `feature/FE-share-products`
  - PR: `https://github.com/NaengpaMaster/Frontend/pull/67`
  - 포함 내용:
    - 가족 냉장고 검증/하이라이트 개선
    - 공유 냉장고 냉장고 사진 버튼 노출
    - 모바일 버튼 레이아웃 개선
    - 회원가입 및 가족 초대 입력 검증 개선

- 웹사이트 메타 정보를 수정했다.
  - 브라우저 탭 title을 `냉파 마스터`에서 `냉파마스터`로 통일했다.
  - `applicationName`을 `냉파마스터`로 추가했다.
  - 사이트 아이콘과 Apple 아이콘을 `/brand/naengpa-master-logo-vertical.png`로 지정했다.

## 문제 해결
- Flyway 중복 migration 오류
  - 문제: 서버 실행 시 `Found more than one migration with version 1` 오류 발생
  - 원인: 소스가 아니라 build 산출물에 `V1__baseline 2.sql` 복제 파일이 남아 있었음
  - 해결: Gradle clean 후 resources를 재생성해 중복 산출물을 제거

- 운영 반영 지연 문제
  - 문제: GitHub에 코드가 반영된 것처럼 보여도 운영 사이트에서는 수정이 보이지 않음
  - 원인: PR merge, 운영 프론트 재배포, CDN 캐시, 브라우저 캐시는 각각 별도 단계임
  - 해결: 원격 main 커밋 포함 여부를 확인하고, 운영 반영은 배포와 캐시 확인이 필요하다고 정리

- 모바일 버튼 세로 배열 문제
  - 문제: 공유 냉장고 화면에서 버튼들이 모바일 폭에 맞지 않아 세로로 떨어짐
  - 원인: 버튼 컨테이너 폭이 좁고 버튼이 줄바꿈되며 배치됨
  - 해결: 버튼 영역에 `flexWrap: nowrap`, `flexShrink: 0`, `whiteSpace: nowrap`, `overflowX: auto`를 적용

## 배운 점
- 발표 자료에는 변수명이나 세부 코드 흐름보다 사용자가 이해할 수 있는 기능 단위 문구가 더 적합하다.
- 트러블슈팅 슬라이드에서는 전체 코드보다 문제를 가장 잘 보여주는 핵심 코드 1개만 보여주는 것이 효과적이다.
- 운영 반영 여부는 `커밋`, `PR 머지`, `배포`, `캐시`를 분리해서 확인해야 한다.
- Flyway 오류는 실제 migration 소스뿐 아니라 build 산출물에 남은 복제 파일 때문에도 발생할 수 있다.
