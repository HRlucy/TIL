- 냉장고 사진 등록 QA를 정리했다.
  - 냉장고 사진 등록은 OCR이 아니라 OpenAI Vision 기반 이미지 분석이라고 정리했다.
  - OCR은 영수증처럼 텍스트를 읽는 기능이고, 냉장고 사진 등록은 이미지 속 식재료 후보를 인식하는 기능이라고 구분했다.
  - OpenAI Vision을 사용한 이유, 구현 방식, 어려웠던 점, 문제 상황, 예외 처리, 보안, 검증, 백업 관점의 답변을 준비했다.

- 위치 기반 재료 나눔 QA를 정리했다.
  - 지도는 Kakao Maps JavaScript API를 사용했다고 설명하기로 했다.
  - 현재 위치는 브라우저 Geolocation API를 사용하고, 백엔드에서는 위도·경도·반경 기준으로 주변 게시글을 필터링한다고 정리했다.
  - 위치 권한이 없을 때 기본 위치와 안내 메시지로 대응하는 흐름을 설명할 수 있게 정리했다.

## 문제 해결
- 발표 질문 범위가 기능 설명에서 기술 구현 방식까지 넓어질 수 있음을 고려했다.
  - 단순히 “무슨 기능을 만들었다”가 아니라 “왜 이 기술을 썼는지”, “어떻게 연결했는지”, “오류나 예외를 어떻게 막았는지”까지 답변을 준비했다.

- OpenAI Vision 사용 이유를 명확히 구분했다.
  - 영수증 등록은 OCR 중심이다.
  - 냉장고 사진 등록은 이미지 속 식재료를 인식해야 하므로 Vision 분석이 적합하다.
  - 직접 모델을 학습하기보다는 MVP 단계에서 범용 Vision 모델을 활용하는 것이 현실적이라고 정리했다.

- AI 결과 신뢰성 문제에 대한 답변을 준비했다.
  - Vision 결과는 항상 정확하지 않기 때문에 자동 등록하지 않는다.
  - 백엔드에서 사전 재료와 매칭한 뒤 후보 상태로 저장한다.
  - 사용자가 최종 확인한 재료만 냉장고에 등록되도록 설계했다.

- 보안과 비용 관련 답변을 준비했다.
  - OpenAI API Key는 프론트에 노출하지 않고 Agent 서버 환경변수에서 관리한다.
  - Vision API 호출 비용이 발생하기 때문에 구독자 전용 기능으로 분리했다.
  - Agent 응답의 usage 정보를 백엔드에 저장해 관리자 AI 사용량 로그에서 확인할 수 있도록 했다.

## 배운 점
- 발표 QA는 기능 설명보다 구현 의도, 기술 선택 이유, 예외 처리, 검증 방식까지 준비해야 한다.
- AI 기능은 “정확하다”가 아니라 “불확실성을 전제로 안전하게 사용한다”는 관점으로 설명하는 것이 중요하다.
- 프론트, 백엔드, Agent의 역할을 명확히 나누어 설명하면 시스템 구조를 이해시키기 쉽다.
- 발표용 코드는 많이 보여주는 것보다 각 기능의 핵심 로직 1개를 선별하는 것이 효과적이다.
