# 냉파마스터 구독/가족공유/공유 장보기 설계 정리

## 오늘 작업 요약

냉파마스터에 프리미엄 구독 기반 가족 공유 기능을 붙이면서, 단순히 같은 냉장고 데이터를 보여주는 것만으로는 사용자 경험과 구독 명분이 애매해질 수 있다는 점을 확인했다. 그래서 가족공유의 핵심을 `각자 계정으로 접근`, `권한 관리`, `행동 이력 기록`, `공유 냉장고/개인 냉장고 분리`로 정리했다.

## 구현한 내용

### 1. 가족 공유 냉장고

프리미엄 구독자가 가족 구성원을 초대하고, 초대받은 사용자가 수락하면 같은 냉장고를 함께 볼 수 있도록 했다.

- 초대는 바로 참여가 아니라 신청/수락 방식으로 변경했다.
- 관리자 계정은 가족 초대 대상에서 제외했다.
- 프리미엄 구독자만 가족공유를 관리할 수 있도록 문구와 UI를 정리했다.
- 가족 구성원은 구성원 삭제 버튼이 보이지 않도록 했다.
- 구독자와 구성원을 구분할 때 `memberId` 타입 차이로 인한 오류를 수정했다.

### 2. 공유 장보기

기존 장보기는 `member_id` 기준이라 가족 공유 냉장고와 맞지 않았다. 가족이 같은 냉장고를 쓰면 장보기 목록도 같이 공유되는 것이 자연스럽다고 판단했다.

변경 방향:

- `shopping_items`에 `fridge_id` 추가
- 장보기 조회/등록/수정/체크/삭제 기준을 `member_id`에서 `fridge_id`로 변경
- 가족 냉장고 구성원이 장보기를 추가하면 같은 가족 냉장고 구성원에게 보이도록 처리
- 장보기에서 냉장고로 반영할 때도 현재 활성 냉장고 기준으로 등록

### 3. 이력 테이블 추가

가족공유가 계정 돌려쓰기와 다른 점은 “누가 했는지”가 남는다는 점이다. 그래서 냉장고 재료와 장보기 모두 행동 이력을 남기도록 했다.

냉장고 재료 이력:

- 등록
- 수정
- 전체 사용
- 일부 사용
- 삭제

장보기 이력:

- 등록
- 수정
- 체크
- 체크 해제
- 냉장고 반영
- 삭제

이력에는 다음 정보를 남긴다.

- 대상 냉장고 ID
- 행동한 회원 ID
- 재료 ID
- 재료명
- 수량
- 행동 타입
- 발생 시각

## 논의한 정책

### 공유 취소 시 데이터 처리

처음에는 가족 구성원을 내보내면 그 구성원이 공유 냉장고에 등록한 냉장고 재료/장보기 항목을 자동 삭제하는 방향을 검토했다. 하지만 이 방식은 데이터 소유권과 사용자 경험 측면에서 문제가 있었다.

예시:

- A: 프리미엄 구독자이자 가족 냉장고 소유자
- B: 가족 구성원
- B가 가족 냉장고에 재료를 등록
- A가 B를 내보냄

이때 B가 등록한 데이터를 삭제하면 A의 가족 냉장고 데이터가 갑자기 사라진다. 반대로 B 입장에서는 공유 중 등록한 데이터가 자기 개인 냉장고에 남는다고 기대할 수도 있다. 그래서 데이터 삭제보다는 접근 권한만 끊는 방식이 더 안전하다고 판단했다.

최종적으로 더 나은 정책은 다음과 같다.

- B의 개인 냉장고는 항상 유지한다.
- B가 A의 가족 공유를 수락하면 기본 화면은 A의 가족 냉장고를 보여줄 수 있다.
- 공유 중 B가 A 가족 냉장고에 등록한 데이터는 A 가족 냉장고 소속 데이터로 남긴다.
- 공유 취소 후 B는 A 가족 냉장고를 더 이상 볼 수 없다.
- 공유 취소 후 B는 다시 자기 개인 냉장고 데이터를 본다.
- 즉, 공유 취소는 데이터 삭제가 아니라 접근 권한 제거가 핵심이다.

## 사용자 경험 이슈

가족 공유를 수락하면 사용자가 보던 데이터가 갑자기 개인 냉장고에서 가족 냉장고로 바뀔 수 있다. 이 경우 사용자는 “내 데이터가 사라졌다”고 느낄 수 있다.

따라서 최소한 다음 UI가 필요하다.

- 현재 보고 있는 냉장고 표시
- 예: `내 냉장고`, `A님의 가족 냉장고`
- 공유 수락 후 안내 문구
- 공유 취소 후 안내 문구

더 좋은 구조는 냉장고 선택 기능을 제공하는 것이다.

- `GET /api/v1/fridges/me/accessible` API 추가
- 사용자가 접근 가능한 냉장고 목록 조회
- 프론트에서 냉장고 선택 드롭다운 제공
- 냉장고/장보기 API에 `fridgeId`를 명시해서 조회/등록

다만 MVP에서는 복잡도를 줄이기 위해 현재 활성 냉장고 기준 자동 전환을 유지하고, 현재 냉장고 표시부터 추가하는 것이 현실적이다.

## 구독 기능의 명확한 이유

가족공유만으로는 구독 명분이 약할 수 있다. 가족이 A 계정을 같이 쓰면 비슷하게 보일 수 있기 때문이다. 따라서 프리미엄의 핵심 가치는 가족공유 하나가 아니라 “자동화 + 공유 + 이력”으로 잡는 것이 더 명확하다.

무료 기능:

- 개인 냉장고 재료 관리
- 재료 등록/수정/사용/삭제
- 소비기한 임박/만료 확인
- 기본 레시피 추천

프리미엄 기능:

- AI 장보기 추천 대화 기능
- 영수증으로 냉장고 재료 추가
- 냉장고 사진 기반 재료 후보 추출
- 가족 공유 냉장고
- 구성원별 활동 이력

구독 문구 방향:

> 직접 입력은 무료, 자동 관리는 프리미엄

> 냉장고 사진과 영수증으로 재료를 빠르게 등록하세요

> 가족과 함께 쓰는 장보기와 냉장고를 AI가 정리해드려요

## 냉장고 사진 자동 등록 공수 판단

냉장고 사진을 찍으면 AI가 재료를 인식해서 냉장고에 넣는 기능도 검토했다.

추천 MVP 방식:

- 사진 업로드
- AI가 재료 후보 추출
- 우리 `products` 데이터와 매칭
- 사용자가 후보를 확인/수정
- 선택한 재료를 냉장고에 일괄 등록

예상 공수:

- MVP 후보 등록 방식: 3~5일
- 완전 자동 등록 방식: 1~2주
- 제품화 수준: 3~5주 이상

완전 자동 등록은 오인식 위험이 크기 때문에 MVP에서는 추천하지 않는다. 사용자 확인 단계를 두는 것이 안정적이다.

## 오늘 배운 점

가족공유 기능은 단순히 같은 데이터를 보여주는 기능이 아니다. 사용자별 계정, 권한, 데이터 소속, 행동 이력이 함께 설계되어야 한다. 특히 공유 취소 시 데이터를 삭제할지, 접근 권한만 제거할지에 따라 사용자 경험이 크게 달라진다.

이번 설계에서 가장 중요한 기준은 다음이다.

- 개인 데이터와 가족 공유 데이터는 분리한다.
- 공유 취소는 데이터 삭제가 아니라 접근 권한 제거로 본다.
- 가족공유의 차별점은 계정 돌려쓰기가 아니라 구성원별 이력과 권한 관리다.
- 구독의 핵심 명분은 가족공유 단독보다 AI 자동화와 함께 묶을 때 더 명확하다.
