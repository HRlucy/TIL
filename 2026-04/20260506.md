## non-static 필드: 개인 사물함
> new로 객체를 만들 때마다 heap에 새로 생성 객체마다 독립적임
private int personalLocker;

## static 필드: 공용 사물함
> 프로그램 시작 시 static 영역에 단 하나만 생성 모든 객체가 공유 static 필드는 클래스명.필드명으로 접근해야 함
public int getPersonalLocker() {
        return personalLocker;
    }

public void setPersonalLocker(int personalLocker) {
    this.personalLocker = personalLocker;
}

## final 변수
1. 읽기만 가능, 변경은 불가
2. final 필드 변경 불가
3. 메서드 - 호출은 가능, 오버라이딩만 불가
4. 이름은 전부 대문자, 단어는 언더스코어로 구분 - SNAKE_CASE 관례

## 디자인 패턴
> 자주 등장하는 문제를 효과적으로 해결하기 위한 검증된 설계 템플릿 싱글톤(singleton)패턴
- 프로그램 전체에서 특정 클래스의 인스턴스가 단 하나만 존재하도록 보장
1. 외부에서 new로 마음대로 객체를 못 만들게 막는다 -> 생성자를 private
2. 클래스 스스로 자기 객체를 딱 하나 만들어 보관한다 -> private static 필드
3. 그 하나의 객체를 외부에 전달해줄 '창구'를 만든다 -> public static 메소드

## 객체 탄생 순서
1. static 초기화 블록 -> 클래스 로드 시 딱 1번
2. 명시적 초기값 -> new 할 때마다
3. 인스턴스 초기화 블록 -> 생성자 직전마다
4. 생성자 -> 최종 마무리

## 초기화 블럭
1. 명시적 초기화 : 필드를 선언하면서 값 할당 객체가 생성될 때 가장 먼저 이 값으로 초기화
2. 인스턴스 초기화 블럭 : 생성자보다 먼저 모든 생성자 공통 실행 오버로딩된 생성자가 여러 개일 때 중복 초기화 코드를 한 곳에 모으는 용도
3. 정적 초기화 블럭 : 클래스가 메모리에 로드될 때 딱 한 번 실행 복잡한 로직(반복문, DB 조회 등)으로 static 필드를 초기화할 때 사용

## 변수
1. 인스턴스 변수(non-static field) - 클래스 영역에 선언, new 키워드로 객체 생성과 함께 heap 영역에 생성 같은 클래스 내 어드 메소드에서든 접근 가능
2. 클래스 변수(static field) - 프로그램 시작과 함께 static 영역에 단 하나 생성 모든 인스턴스가 공유하며 프로그램 종료 시까지 사라지지 않음
3. 지역 변수(local variable) - 메소드 블록 안에 선언
