# TIL 2026-08-10 - OAuth2, Flyway, LLM 사용량 로그 정리

## 작업 배경
- 카카오/네이버 OAuth2 로그인과 소셜 계정 연동 흐름을 마무리했다.
- 백엔드/프론트 최신화 과정에서 Flyway 로컬 파일과 RDS 적용 이력 불일치가 발생했다.
- AI 장보기 추천 실패 시 `llm_usage_logs.feature_type` 누락으로 DB insert 오류가 발생했다.

## OAuth2 회원가입/로그인 정리
- 신규 소셜 가입은 provider 이메일 제공 여부와 무관하게 추가정보 입력 화면을 거치도록 정리했다.
- 추가정보 입력 단계에서 이메일 인증, 닉네임, 가구 유형을 함께 받도록 수정했다.
- `members.email`은 서비스 메일 발송용 이메일로 사용하고, `provider_email`은 소셜 제공자 응답값으로 별도 보관한다.
- 소셜 계정 식별은 이메일이 아니라 `provider + provider_user_id` 기준으로 처리한다.
- 마이페이지에서 카카오/네이버 계정 연동 및 해지 흐름을 확인했다.

## OAuth2 예외/QA 처리
- OAuth2 실패, 취소, 중복 연동, 비활성/탈퇴 회원 케이스를 사용자에게 안내하도록 처리했다.
- 로그인 화면뿐 아니라 로그인된 상태의 마이페이지 연동 실패/취소도 전역에서 안내되도록 보강했다.
- 비활성/탈퇴 회원 OAuth2 로그인 차단 케이스를 테스트로 검증했다.
- GitHub 이슈 `#291`, `#292`, `#293` 체크리스트를 구현 상태에 맞게 갱신했다.

## Flyway 이슈 정리
- 로컬 `dev` 브랜치가 `origin/dev`보다 뒤처져 있어 최신화했다.
- RDS `flyway_schema_history`에는 `V10`이 이미 적용되어 있었지만 로컬에는 추적되지 않은 상태였다.
- `V10__add_receipt_payment_settlement_tables.sql`이 없으면 `Detected applied migration not resolved locally: 10` 오류가 발생했다.
- 복원한 `V10` 파일 앞에 잘못된 문자 `가`가 붙어 checksum mismatch가 발생했다.
- 잘못된 문자를 제거하고 `processResources`를 재실행해 Flyway 검증을 통과시켰다.
- `build/classes`, `build/resources`에 남아 있던 `* 2` 중복 산출물을 제거해 main class 중복 문제를 해결했다.

## LLM 사용량 로그 오류 해결
- 오류 메시지:
  - `null value in column "feature_type" of relation "llm_usage_logs" violates not-null constraint`
- 원인:
  - `V16`에서 `llm_usage_logs.feature_type`이 `NOT NULL`로 추가됐지만 `LlmUsageLog` 엔티티에는 필드가 없었다.
  - 성공/실패 로그 저장 시 `feature_type`이 null로 insert됐다.
- 조치:
  - `LlmUsageLog` 엔티티에 `featureType` 매핑을 추가했다.
  - 장보기 추천 로그 기본값을 `SHOPPING_RECOMMENDATION`으로 저장하도록 수정했다.
  - 사용자/관리자 LLM 사용량 응답 DTO에도 `featureType`을 포함했다.
  - 관련 테스트에서 `featureType` 저장 여부를 검증하도록 보강했다.

## 검증
- `./gradlew bootRun`
  - Flyway validate 성공
  - Tomcat 8080 기동 성공 확인 후 종료
- `./gradlew test --tests OAuth2SocialAccountApiTests`
  - OAuth2 계정 연동/해지/비활성/추가정보 프로필 저장 테스트 통과
- `./gradlew test --tests LlmUsageLogServiceTests --tests AgentShoppingRecommendationServiceTests`
  - LLM 사용량 로그와 AI 장보기 추천 관련 테스트 통과
- 프론트 `npm run build`
  - OAuth2 추가정보 화면과 소셜 로그인 라우팅 빌드 통과

## 주의 사항
- `V10__add_receipt_payment_settlement_tables.sql`은 현재 RDS history에 이미 적용된 파일이므로 삭제하면 안 된다.
- `V10` 파일은 현재 로컬에서 untracked 상태이므로, 해당 작업 주체와 확인 후 git에 포함해야 한다.
- Flyway migration 파일은 한 번 RDS에 적용되면 내용을 수정하지 말고 후속 버전으로 변경해야 한다.
- `feature_type`은 현재 장보기 추천 기준으로 `SHOPPING_RECOMMENDATION`을 기본 저장한다.
- 추후 문의 Q&A 등 다른 AI 기능이 로그를 쓰면 `INQUIRY_QNA`처럼 기능별 타입을 명시하는 생성 메서드를 분리하는 것이 좋다.
