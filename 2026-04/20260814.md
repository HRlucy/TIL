## 작업 내용
- 사용자 메뉴 구조를 정리했다.
  - 기존 하단/사이드 메뉴에서 `나눔`, `퀴즈`, `문의`, `구독 관리`를 분리했다.
  - 주요 메뉴는 `홈`, `냉장고`, `레시피`, `장보기`, `나의 냉파` 중심으로 정리했다.
  - `나의 냉파`를 모달이 아닌 일반 페이지 탭으로 전환했다.

- `나의 냉파` 페이지를 구성했다.
  - `재료 함께 나눔`, `퀴즈`, `문의`, `구독 관리`, `마이페이지 수정` 메뉴를 아이콘 카드로 배치했다.
  - 모바일에서는 아이콘 메뉴가 아래로 보이는 2열 그리드 형태가 되도록 수정했다.
  - 하위 메뉴에서는 `‹ 나의 냉파` 뒤로가기 형태로 돌아갈 수 있게 구성했다.

- `마이페이지 수정` 화면을 별도 페이지로 분리했다.
  - 기존 마이페이지 내부 펼침 방식에서 `mypage-edit` 탭 페이지 방식으로 변경했다.
  - `마이페이지 수정` 상단 헤더를 다른 페이지와 동일한 흰색 헤더 블록 형식으로 맞췄다.
  - `기본 정보`, `가구 유형`, `소셜 로그인 연동`, `선호 음식`, `못 먹는 재료` 제목을 볼드체로 정리했다.
  - 수정 폼 영역은 별도 흰색 카드로 분리했다.

- 홈 화면 UI를 정리했다.
  - 홈 상단의 사람 모양 마이페이지 버튼을 제거했다.
  - 마이페이지 진입은 `나의 냉파` 메뉴로 통일했다.

- 회원탈퇴 기능을 구현했다.
  - 프론트 `나의 냉파` 하단에 `회원탈퇴`와 `로그아웃` 버튼을 좌우로 배치했다.
  - 회원탈퇴 클릭 시 `정말 회원을 탈퇴하시겠습니까?` 확인창을 표시했다.
  - 탈퇴 성공 시 토큰을 제거하고 인증 상태를 초기화하도록 연결했다.
  - 백엔드에 `DELETE /api/v1/members/me` API를 추가했다.
  - 탈퇴는 실제 삭제가 아니라 기존 정책에 맞춰 `INACTIVE` 상태와 `deletedAt`을 사용하는 소프트 탈퇴로 처리했다.

- 구독 중 회원의 탈퇴 차단 로직을 보완했다.
  - 처음에는 본인 결제 구독만 확인해서 가족공유 등 실제 프리미엄 상태를 놓칠 수 있었다.
  - `SubscriptionService.getMySubscription(email)` 기준으로 실제 접근 가능한 프리미엄 상태를 확인하도록 수정했다.
  - `premium=true`이고 `cancelReserved=false`면 탈퇴를 막는다.
  - 안내 문구는 `현재 구독 중이라 회원탈퇴가 불가합니다. 구독 취소 후 다시 시도해주세요.`로 맞췄다.
  - 프론트에서도 탈퇴 실패 시 토큰을 지우지 않도록 수정했다.

- 재료 함께 나눔 기능을 보완했다.
  - 내가 참여한 나눔 목록 조회 API를 추가했다.
  - 백엔드에 `GET /api/v1/community-shares/me/joined`를 추가했다.
  - 처음에는 `내 참여 나눔`을 `나의 냉파` 별도 페이지로 만들었지만, 요구사항에 맞춰 제거했다.
  - 최종 구조는 `재료 함께 나눔` 화면 내부 탭으로 정리했다.
    - `주변 나눔`
    - `내 나눔`
    - `나눔 참여`
  - `나눔 참여` 탭에서 내가 참여한 나눔 목록을 확인하도록 연결했다.
  - `내 나눔`, `나눔 참여` 탭에서는 지도/현재위치/반경 UI가 보이지 않도록 수정했다.
  - 세 탭은 한 줄 3등분으로 보이도록 변경했다.

- 구독 관리 화면 UI를 맞췄다.
  - 구독 관리 헤더를 다른 화면과 동일한 흰색 헤더 블록 형식으로 변경했다.
  - 라벨, 제목, 설명의 크기와 간격을 통일했다.

- 백엔드/프론트/에이전트 최신화를 진행했다.
  - Backend는 `origin/dev` 기준 최신 상태 확인.
  - Frontend는 `origin/main`을 fast-forward로 반영하고 로컬 변경을 복원했다.
  - Agent-dev는 `origin/dev`를 fast-forward로 반영하고 기존 미추적 파일을 복원했다.
  - stash/pop 과정에서 충돌은 없었다.

## 문제 해결
- `git push feature/BE-share-products` 명령 오류를 확인했다.
  - Git이 브랜치명을 원격 저장소명으로 해석해서 실패한 문제였다.
  - 올바른 명령은 `git push -u origin feature/BE-share-products`임을 정리했다.

- 운영 배포 도메인에서 나눔 API 404 문제를 확인했다.
  - `https://naengpa.com`은 `https://www.naengpa.com`으로 302 리다이렉트되고 있었다.
  - `GET /api/v1/community-shares/me/joined`는 오늘 추가한 신규 API라 운영 백엔드에 아직 배포되지 않으면 404가 발생한다.
  - 배포 후에는 비로그인 curl 기준 `401/403`이 정상이고, `404`가 아니면 API 라우트는 올라간 것으로 볼 수 있다.

## 배운 점
- 프론트에서 메뉴를 숨기는 것만으로는 사용자에게 기능 위치가 명확하게 전달되지 않는다.
  - 사이드바/하단 네비에는 핵심 메뉴만 남기고, 세부 기능은 `나의 냉파` 같은 허브 페이지에 모으는 방식이 더 자연스럽다.

- 회원탈퇴처럼 계정 상태를 바꾸는 기능은 프론트 차단만으로는 부족하다.
  - 백엔드에서 실제 구독 상태를 기준으로 반드시 한 번 더 검증해야 한다.
  - API 실패 시 프론트가 토큰을 지워버리면 사용자는 탈퇴가 된 것처럼 오해할 수 있다.

- 운영 404는 프론트 코드 문제일 수도 있지만, 신규 API의 경우 운영 백엔드 배포 여부를 먼저 확인해야 한다.
  - 특히 프론트가 최신 기능을 호출하는데 백엔드가 아직 배포되지 않은 경우가 가장 흔하다.
